# 🔥 智能 Glob 搜索 - 元编程架构设计

## 🎯 问题本质

**传统方式的致命缺陷**：
```rust
// ❌ 数据倾倒模式：85,005 个文件 → 386 万 tokens → 上下文爆炸
fn glob_search(pattern: &str) -> String {
    walkdir(pattern)
        .map(|entry| entry.path().display().to_string())
        .join("\n")  // 一次性生成所有输出
}
```

**根本原因**：
1. **数据即代码**：将所有数据原样输出到对话中
2. **缺乏边界控制**：没有限制输出大小的机制
3. **无视图抽象**：用户被迫接收全部数据

---

## 🏗️ 元编程架构设计

### 核心原则

```
【声明式意图】→ 用户声明"想要什么"
      ↓
【智能推断】→ 系统分析"真正需要什么"
      ↓
【元数据生成】→ 零拷贝生成结构化摘要
      ↓
【惰性求值】→ 按需展开详细信息
      ↓
【流式处理】→ 边生成边消费
```

### 架构分层

```text
┌─────────────────────────────────────────────────────────┐
│                  用户接口层（声明式）                     │
│  StreamPipeline::new("*.rs").with_limit(10).execute()  │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                意图分析层（元编程）                       │
│  SearchIntent::from_pattern() → 自动推断用户意图         │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                视图选择层（智能路由）                     │
│  Exploration → Overview | Precise → Sampled | ...      │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                数据访问层（惰性加载）                     │
│  PaginationNavigator | StreamingSearchResults          │
└─────────────────────────────────────────────────────────┘
                            ↓
┌─────────────────────────────────────────────────────────┐
│                存储层（零拷贝）                          │
│  元数据 + LRU 缓存 + 虚拟化列表                          │
└─────────────────────────────────────────────────────────┘
```

## 💡 三大解决方案

### 方案 1：智能元数据生成器

**核心理念**：用**结构化摘要**替代**原始列表**

```rust
// ✅ 元数据驱动：85,005 个文件 → 几百 tokens
pub struct SearchMetadata {
    total_files: usize,           // 总数
    total_size: u64,              // 总大小
    file_types: HashMap<...>,     // 类型分布
    largest_files: Vec<...>,      // 最大 10 个
    sample: Vec<PathBuf>,         // 采样 100 个
}

// 输出示例：
// 📊 Search Results Overview
// ╟─────────────────────────────────
// │ Total Files: 85,005
// │ Total Size: 2.3 GB
// │ File Types: rs, toml, json, md...
// │ Largest Files: 10 items
// ╰─────────────────────────────────
// 💡 Use .expand() to see detailed results
```

**关键技术**：
- **流式处理**：一次遍历，收集元数据
- **启发式采样**：每 1000 个文件采样 1 个
- **零拷贝**：仅存储摘要，不复制完整列表

---

### 方案 2：交互式分页系统

**核心理念**：**虚拟化列表**，只渲染可见页

```rust
// ✅ 分页导航：50 个文件/页 → 可控的 tokens 消耗
pub struct PaginationNavigator {
    page_size: 50,          // 每页 50 个
    cache: LruCache,        // LRU 缓存
    current_page: usize,    // 当前页
}

// 输出示例：
// ╭─ Page 1 of 1701 (Files 1-50 of 85005) ─╮
// │     1 │ src/main.rs
// │     2 │ src/lib.rs
// │   ... │ (48 more files)
// ╰─ Next ▶                           ╯
//
// 用户输入: "next" → 加载第 2 页
```

**关键技术**：
- **LRU 缓存**：缓存最近访问的 10 页
- **预加载**：自动预加载前后各 2 页
- **零拷贝视图**：视图与数据分离

---

### 方案 3：流式处理管道

**核心理念**：**生产者-消费者模式**，边扫描边处理

```rust
// ✅ 流式处理：实时过滤，无需等待完整结果
let results = StreamPipeline::new("**/*.rs")
    .with_filter(Arc::new(|path| {
        path.extension().map_or(false, |e| e == "rs")
    }))
    .with_limit(10)
    .execute();

// 实时处理，边读边过滤
results.process(|path| {
    println!("Found: {}", path.display());
    Ok(())
}).await;
```

**关键技术**：
- **异步流**：使用 `futures::Stream` 实现流式处理
- **背压控制**：缓冲区限制，防止内存溢出
- **水库采样**：算法保证均匀采样，无需遍历全部数据

## 🎯 元编程设计模式

### 1. 意图推断（Intent Inference）

```rust
// 用户只需声明搜索模式
let pattern = "**/*.rs";

// 系统自动推断意图
let intent = SearchIntent::from_pattern(pattern);
// → IntentType::Precise（精确查找）
// → expected_count: 100（预计约 100 个结果）
```

### 2. 智能路由（Smart Routing）

```rust
// 根据意图和数据量自动选择视图
match (intent_type, result_count) {
    (Exploratory, _)           → Overview,      // 显示概览
    (Precise, count) if count < 100 → Sampled,  // 显示采样
    (_, count) if count > 10000 → Paged,       // 分页显示
    _                           → Full,         // 完整显示（带警告）
}
```

### 3. 链式构建器（Fluent Builder）

```rust
// 声明式 DSL，自动配置整个管道
StreamPipeline::new("pattern")
    .with_filter(...)      // 链式过滤器
    .with_limit(100)       // 限制数量
    .with_batch_size(50)   // 批次处理
    .execute();            // 执行（元编程：应用所有配置）
```

### 4. 惰性求值（Lazy Evaluation）

```rust
// 不会立即计算，仅在需要时计算
let results = SearchResults::search("**/*");

// 调用 expand() 时才真正加载数据
results.expand();
```

## 🎓 元编程精髓总结

### 核心思想

1. **代码即数据**
   - 配置即代码，声明即实现
   - 数据结构驱动行为

2. **零重复原则**
   - 重复逻辑由生成器自动产生
   - DRY（Don't Repeat Yourself）的极限化

3. **声明式设计**
   - 声明"想要什么"，而非"怎么做"
   - 让系统自动决定最佳实现

4. **惰性求值**
   - 仅在需要时计算
   - 避免不必要的开销
