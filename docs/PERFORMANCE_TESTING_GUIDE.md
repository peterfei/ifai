# 🧪 性能测试指南 - 10,000+ 条消息场景

## 📋 测试目标

验证 `VirtualMessageList` 在大量消息场景下的性能优化效果：
- **缓存命中率**: 应该 > 80%（流式输出时）
- **渲染时间**: 单次过滤应该 < 50ms
- **UI 响应**: 流式输出期间 UI 应该保持响应，无卡顿

## ⚠️ 重要说明

### E2E 自动化测试
由于性能测试需要真实的 AI 流式响应，E2E 测试目前**需要配置真实的 AI API** 才能运行。

如果您没有 API key，请使用**手动测试**方法（推荐）。

### 手动测试（推荐）
手动测试是最简单、最可靠的性能验证方法，无需任何 API 配置。

## 📊 性能指标解读

### ✅ 优秀（优化生效）

| 指标 | 阈值 | 说明 |
|------|------|------|
| 缓存命中率 | > 80% | 流式输出时大部分渲染命中缓存 |
| 平均渲染时间 | < 10ms | 过滤操作很快 |
| 最大渲染时间 | < 50ms | 没有明显的卡顿 |
| 流式输出时长 | < 5 秒 | 响应及时 |

### ⚠️ 需要优化

| 指标 | 问题表现 | 可能原因 |
|------|----------|----------|
| 缓存命中率 < 50% | 大量缓存未命中 | 缓存逻辑未生效 |
| 渲染时间 > 100ms | 明显卡顿 | 每次都在遍历 10,000+ 条消息 |
| UI 冻结 | 无法滚动或点击 | 主线程阻塞 |

## 🐛 常见问题

### Q: Console 显示 `找不到 activeThreadId`

**原因**: 没有打开任何对话

**解决**: 先在应用中创建或选择一个对话，然后再运行生成脚本

### Q: 生成数据后应用崩溃

**原因**: 一次性生成太多数据

**解决**: 修改 `generate-test-data.js` 中的 `messageCount`：
```javascript
const messageCount = 5000; // 先尝试 5000 条
```

### Q: 性能监控没有输出

**原因**: 可能是日志级别设置问题

**解决**: 在 Console 中手动启用日志：
```javascript
// 检查是否有缓存日志输出
// 如果没有，检查 logger 配置
```

### Q: 缓存命中率很低（< 50%）

**原因**: `useStableMessages` 的缓存逻辑可能未生效

**解决**: 检查以下几点：
1. 确认运行的是最新代码（commit 76f2324 或更新）
2. 检查 Console 是否有 `[useStableMessages]` 日志
3. 如果没有日志，说明 hook 未被调用
