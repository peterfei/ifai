## 系统概述

### 什么是多智能体协作系统？

多智能体协作系统是一个用于协调多个 AI 智能体共同完成复杂任务的工作流引擎。它允许你：

- **定义工作流**: 使用代码或 YAML 配置定义复杂的任务流程
- **并行执行**: 自动识别并执行可并行化的任务
- **智能调度**: 基于 DAG（有向无环图）的拓扑排序和调度
- **灵活通信**: 智能体之间支持点对点、广播、主题订阅等多种通信模式
- **容错机制**: 支持重试、超时、失败快速停止等策略

### 系统特性

| 特性 | 描述 | 状态 |
|------|------|------|
| **工作流定义** | 支持代码和 YAML 两种方式 | ✅ |
| **DAG 调度** | 基于拓扑排序的智能调度 | ✅ |
| **并行执行** | 自动识别并行节点 | ✅ |
| **智能体类型** | 8 种预定义智能体类型 | ✅ |
| **条件执行** | 支持基于条件的分支 | ✅ |
| **变量替换** | 支持工作流级变量 | ✅ |
| **消息总线** | 高性能异步消息传递 | ✅ |
| **通信模式** | 点对点、广播、主题、组播 | ✅ |
| **会话管理** | 多方会话跟踪 | ✅ |
| **容错机制** | 重试、超时、失败策略 | ✅ |

## 核心概念

### 1. 工作流（Workflow）

工作流是一个由节点和边组成的有向无环图（DAG），用于描述任务的执行顺序和依赖关系。

```rust
pub struct Workflow {
    pub id: String,           // 唯一标识符
    pub name: String,         // 显示名称
    pub description: String,  // 描述
    pub nodes: Vec<WorkflowNode>,  // 节点列表
    pub edges: Vec<WorkflowEdge>,  // 边列表
    pub variables: HashMap<String, String>,  // 变量
}
```

### 2. 节点（Node）

节点代表工作流中的一个任务单元，由特定类型的智能体执行。

```rust
pub struct WorkflowNode {
    pub id: String,           // 节点 ID
    pub agent_type: AgentType, // 智能体类型
    pub label: Option<String>, // 显示标签
    pub config: AgentConfig,  // 配置
}
```

### 3. 边（Edge）

边表示节点之间的依赖关系。

```rust
pub struct WorkflowEdge {
    pub from: String,         // 源节点 ID
    pub to: String,           // 目标节点 ID
    pub condition: Option<String>, // 执行条件
}
```

### 4. 智能体类型（Agent Type）

系统支持 8 种预定义的智能体类型：

| 类型 | 说明 | 用途 |
|------|------|------|
| `Explore` | 代码探索 | 分析代码结构、依赖关系 |
| `Review` | 代码审查 | 检查代码质量、发现问题 |
| `Refactor` | 代码重构 | 生成重构建议 |
| `Test` | 测试生成 | 生成测试用例 |
| `Doc` | 文档生成 | 生成代码文档 |
| `TaskBreakdown` | 任务拆解 | 将复杂任务分解为子任务 |
| `ProposalGenerator` | 提案生成 | 生成技术提案 |
| `GeneralPurpose` | 通用目的 | 通用任务处理 |

## 架构设计

### 系统分层架构

```
┌─────────────────────────────────────────────────────┐
│                   应用层                            │
│         (YAML 配置、API 调用、UI)                   │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                 工作流引擎                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐         │
│  │ Parser   │  │Validator │  │Scheduler │         │
│  └──────────┘  └──────────┘  └──────────┘         │
│  ┌──────────┐  ┌──────────┐                        │
│  │  Runner  │  │ Executor │                        │
│  └──────────┘  └──────────┘                        │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│                 通信系统                            │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐         │
│  │MessageBus│  │ Channel  │  │ Session  │         │
│  └──────────┘  └──────────┘  └──────────┘         │
└─────────────────────────────────────────────────────┘
                         ↓
┌─────────────────────────────────────────────────────┐
│               智能体层                              │
│      (Explore, Review, Refactor, Test, ...)         │
└─────────────────────────────────────────────────────┘
```

### 执行流程

```
1. 定义工作流 (YAML/代码)
        ↓
2. 解析和验证 (Parser + Validator)
        ↓
3. 调度 (Scheduler - 拓扑排序)
        ↓
4. 执行 (Runner - 按组并行执行)
        ↓
5. 节点执行 (Executor - 调用智能体)
        ↓
6. 结果汇总
```

### 创建你的第一个工作流

#### 方法 1: 使用代码

```rust
use ifai::agent_system::workflow::*;

fn main() {
    // 创建工作流
    let mut workflow = Workflow::new("my-workflow", "我的第一个工作流")
        .with_description("探索并审查代码");

    // 添加节点
    workflow
        .add_node(WorkflowNode::new("explore", AgentType::Explore))
        .add_node(WorkflowNode::new("review", AgentType::Review));

    // 添加依赖
    workflow.add_edge(WorkflowEdge::new("explore", "review"));

    // 验证
    workflow.validate().expect("工作流验证失败");

    println!("工作流创建成功！");
}
```

```yaml
  - id: "review"
```

## 工作流引擎

### 工作流解析器（WorkflowParser）

将 YAML 配置解析为工作流对象。

```rust
use ifai::agent_system::workflow::WorkflowParser;

// 从字符串解析
let workflow = WorkflowParser::from_str(yaml_content)?;

// 从文件解析
let workflow = WorkflowParser::from_file("workflow.yaml")?;
```

### 工作流验证器（WorkflowValidator）

验证工作流的正确性：

- ✅ 节点 ID 唯一性
- ✅ 边引用的节点存在性
- ✅ 无循环依赖

```rust
use ifai::agent_system::workflow::WorkflowValidator;

let result = workflow.validate();
match result {
    Ok(_) => println!("工作流有效"),
    Err(e) => println!("验证失败: {:?}", e),
}
```

### 工作流调度器（WorkflowScheduler）

使用 Kahn 算法进行拓扑排序，识别可并行的节点组。

```rust
use ifai::agent_system::workflow::WorkflowScheduler;

let schedule = WorkflowScheduler::schedule(&workflow)?;

// 获取执行顺序
println!("执行顺序: {:?}", schedule.execution_order);

// 检查两个节点是否可以并行
if schedule.can_execute_in_parallel("node1", "node2") {
    println!("这两个节点可以并行执行");
}

// 获取节点所在的并行组
let group = schedule.get_node_group("node1");
```

### 工作流运行器（WorkflowRunner）

执行工作流并管理节点状态。

```rust
use ifai::agent_system::workflow::WorkflowRunner;

// 使用默认配置
let runner = WorkflowRunner::with_default_config(workflow)?;

// 使用自定义配置
let config = RunnerConfig {
    max_concurrent_nodes: 10,
    node_timeout_secs: 600,
    max_retries: 3,
    fail_fast: true,
};
let runner = WorkflowRunner::new(workflow, config)?;

// 执行工作流
let result = runner.run().await?;

// 控制执行
runner.pause().await?;
runner.resume().await?;
runner.cancel().await?;
```

## 通信系统

### 消息类型

#### 数据消息（DataMessage）

```rust
use ifai::agent_system::communication::Message;

let msg = Message::data(
    "agent1".to_string(),
    "analysis_result",
    serde_json::json!({"issues": 5, "score": 85}),
);
```

#### 控制消息（ControlMessage）

```rust
use ifai::agent_system::communication::{Message, ControlMessage};

let msg = Message::control(
    "agent1".to_string(),
    ControlMessage::Start {
        config: Some(serde_json::json!({"mode": "fast"})),
    },
);
```

#### 状态消息（StatusMessage）

```rust
use ifai::agent_system::communication::{Message, StatusMessage};

let msg = Message::status(
    "agent1".to_string(),
    StatusMessage::Progress {
        current: 3,
        total: 10,
        message: "处理中".to_string(),
    },
);
```

### 消息总线（MessageBus）

```rust
use ifai::agent_system::communication::MessageBus;
use std::sync::Arc;

let bus = Arc::new(MessageBus::with_default_config());

// 订阅消息
let routes = HashSet::from([
    RouteKey::Direct("agent1".to_string()),
    RouteKey::Topic("updates".to_string()),
]);
let mut receiver = bus.subscribe("agent1".to_string(), routes).await?;

// 发送消息
bus.send(message).await?;

// 发布到主题
bus.publish("updates".to_string(), message).await?;

// 获取消息历史
let history = bus.get_history(Some(10)).await;
```

### 通信通道（AgentChannel）

```rust
use ifai::agent_system::communication::AgentChannel;

// 创建点对点通道
let channel = AgentChannel::direct("agent1".to_string(), bus).await?;

// 分离发送器和接收器
let (sender, mut receiver) = channel.split();

// 发送消息
sender.send_data(
    "agent2".to_string(),
    "result",
    serde_json::json!({"data": "value"}),
).await?;

// 接收消息
if let Some(msg) = receiver.recv().await {
    println!("收到消息: {:?}", msg);
}
```

### 会话管理

```rust
use ifai::agent_system::communication::SessionManager;

let manager = SessionManager::new();

// 创建会话
let session = manager.create_session(vec![
    "agent1".to_string(),
    "agent2".to_string(),
]).await;

// 获取会话
let session = manager.get_session("session_xxx").await;

// 获取智能体的所有会话
```

```yaml

    label: "代码质量审查"

      severity_threshold: 2

  - id: "refactor"
    agentType: "refactor"

  - id: "test"

    label: "生成测试用例"

  - id: "document"
    agentType: "doc"
    label: "生成文档"

edges:
  - from: "explore"
    to: "review"
  - from: "review"
    to: "refactor"
  - from: "review"
    to: "test"
  - from: "refactor"
    to: "document"
  - from: "test"
    to: "document"
```

### 示例 2: 并行执行

```rust
// explore -> (test, doc) -> merge
let mut workflow = Workflow::new("parallel-example", "并行示例");

workflow
    .add_node(WorkflowNode::new("explore", AgentType::Explore))
    .add_node(WorkflowNode::new("test", AgentType::Test))
    .add_node(WorkflowNode::new("doc", AgentType::Doc))
    .add_node(WorkflowNode::new("merge", AgentType::GeneralPurpose))
    .add_edge(WorkflowEdge::new("explore", "test"))
    .add_edge(WorkflowEdge::new("explore", "doc"))
    .add_edge(WorkflowEdge::new("test", "merge"))
    .add_edge(WorkflowEdge::new("doc", "merge"));

// 调度后会发现 test 和 doc 可以并行执行
let schedule = WorkflowScheduler::schedule(&workflow)?;
println!("并行组: {:?}", schedule.parallel_groups);
```

### 示例 3: 条件执行

```rust
let mut edge = WorkflowEdge::new("check", "fix");
edge.condition = Some("${has_issues} == true".to_string());

workflow.add_edge(edge);
```

## 最佳实践

### 1. 工作流设计

**DO:**
- ✅ 保持工作流简洁，单个工作流不超过 20 个节点
- ✅ 使用有意义的节点 ID 和标签
- ✅ 合理设置并行任务以提高效率
- ✅ 使用变量管理可配置参数

**DON'T:**
- ❌ 创建过于复杂的嵌套依赖
- ❌ 在单个工作流中混合不相关的任务
- ❌ 忽略错误处理

### 2. 智能体选择

| 任务类型 | 推荐智能体 |
|---------|----------|
| 分析代码结构 | `Explore` |
| 检查代码质量 | `Review` |
| 改进代码 | `Refactor` |
| 编写测试 | `Test` |
| 生成文档 | `Doc` |

### 3. 配置管理

```rust
// 好的做法：使用变量
let mut workflow = Workflow::new("workflow", "工作流");
workflow.variables.insert("target".to_string(), "/src".to_string());

// 避免硬编码
let config = AgentConfig {
    target: Some("${target}".to_string()),
    ..Default::default()
};
```

### 4. 错误处理

```rust
let runner = WorkflowRunner::with_default_config(workflow)?;

match runner.run().await {
    Ok(result) => {
        if result.is_all_success() {
            println!("所有节点执行成功");
        } else {
            println!("部分节点失败: {:?}", result);
        }
    }
    Err(e) => {
        eprintln!("工作流执行失败: {:?}", e);
        // 实现重试或回滚逻辑
    }
}
```

### 5. 性能优化

- **并行化**: 尽可能设计可并行执行的节点
- **超时设置**: 为每个节点设置合理的超时时间
- **资源限制**: 使用 `max_concurrent_nodes` 限制并发数

```rust
let config = RunnerConfig {
    max_concurrent_nodes: num_cpus::get(),  // 基于 CPU 核心数
    node_timeout_secs: 300,                  // 5 分钟超时
    ..Default::default()
};
```

## 故障排除

### 常见问题

#### 1. 循环依赖错误

```
Error: WorkflowValidationError::CycleDetected
```

**原因**: 工作流中存在循环依赖。

**解决方案**:
- 检查边的定义，确保没有形成环
- 使用 `WorkflowValidator::find_cycle()` 定位循环

```rust
if let Err(e) = workflow.validate() {
    if let WorkflowValidationError::CycleDetected(path) = e {
        println!("发现循环: {:?}", path);
    }
}
```

#### 2. 节点未执行

**原因**: 节点可能因为条件不满足或前置节点失败而未执行。

**解决方案**:
- 检查条件表达式的正确性
- 检查前置节点的执行状态
- 查看 `WorkflowResult.node_results` 了解详情

#### 3. 执行超时

```
Error: Node execution timeout
```

**原因**: 节点执行时间超过配置的超时时间。

**解决方案**:
- 增加 `node_timeout_secs` 配置
- 检查智能体是否存在性能问题
- 考虑将大任务拆分为小任务

#### 4. 消息未送达

**原因**: 智能体未正确订阅消息或消息已过期。

**解决方案**:
- 确保接收方已订阅正确的路由键
- 检查消息的 TTL 设置
- 使用消息历史功能调试
